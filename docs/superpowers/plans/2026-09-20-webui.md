# OpenEPW Web UI Implementation Plan

> **For agentic workers:** Use `superpowers:executing-plans` for native inline
> execution after owner approval. Follow checkbox steps task by task. A final
> independent review is recommended; there are no routine human gates between tasks.

**Status:** approved by the owner on 2026-09-20. Local-first, single-user deployment confirmed. Execute autonomously through substantial completion; collect minor issues and defer only documented blockers.
**Goal:** Deliver a small dockable OpenEPW UI with real manual/scripted workflows,
geospatial interaction, result inspection, complete API references and source access.
**Architecture:** `ui/` is an independent frontend project in this repository.
Typed REST calls connect it to the canonical Python service. Small additive backend
endpoints serve job history and weather previews; science stays in Python.
**Tech Stack:** React/TypeScript/Vite, FlexLayout, React Aria, Zustand, MapLibre,
Geist/Lucide, ECharts, Vitest/Playwright; existing FastAPI/Pydantic/SQLite backend.
**Spec:** [approved design](../specs/2026-09-20-webui-design.md). Read both documents.

## Global constraints

- Preserve `feature/webui`; normal human authorship and `fix(topic): description` commits.
- Local-first, single-user deployment is approved.
- React code lives in `ui/`; Python retains declared 3.11+ support and independent packaging.
- Node 24 and TypeScript 6 are the reference baseline, subject to a checked clean install.
- Browser traffic uses REST; existing MCP remains available and documented.
- No LLM, fake production workflows/data, EnergyAtlas branding or energy-model panels.
- No repository extraction, PyPI publication, paid service or new account in this milestone.
- Runtime keys stay in Python; never copy `.env.local` or reference datasets.
- Preserve source/scenario/window/calendar/QC semantics; no JS weather transformation engine.
- Update architecture/features/roadmap and provenance as each delivered slice changes them.

## Review focus

1. Stale/out-of-order discovery after a request edit must not replace current state (Task 3).
2. Reload/retry/double click must not submit the same reviewed plan twice (Tasks 1 and 3).
3. Missing solar, mixed source years and noleap output must remain visible in charts (Tasks 1 and 5).
4. Docking/theme changes and tile/WebGL failure must not break request entry (Tasks 2 and 4).
5. Script cancellation must distinguish stopping UI work from cancelling a server job (Task 6).

## Task 1 — Typed API support for a real UI

**Files:** modify `src/openepw/{api/app.py,models/__init__.py,service.py,jobs/store.py}`;
create `src/openepw/preview.py`, `scripts/export_openapi.py`,
`tests/unit/test_ui_api.py`, `tests/unit/test_preview.py`.

**Interfaces:** existing WeatherRequest/FutureRequest/WeatherPlan/WeatherJob/
ArtifactRef remain canonical. Add `JobListResponse(items: list[WeatherJob],
next_cursor: str | None)` and a typed preview response described in the design.
Service method `preview_artifact(artifact_id, start=0, limit=168, variables=None)`
resolves/checksums an EPW and calls preview functions. No client filesystem path.

- Add failing API tests for typed existing responses, stable two-page job
  listing, bad cursor/limit, missing artifact, signal upload rejection and auth.
  Include this boundary assertion, using the authenticated test client fixture:
  `assert client.get('/v1/jobs?limit=101').status_code == 422`.
- Add preview tests on synthetic Gregorian and noleap EPWs: missing GHI stays
  null; a missing day reduces valid counts; solar sums versus temperature means;
  UTC interval ends/standard offset remain explicit; never emit NaN JSON.
- Run `python -m pytest tests/unit/test_ui_api.py tests/unit/test_preview.py -q`
  and confirm the new behavior fails before implementing it.
- Add response models without breaking successful existing response shapes.
  Paginate by persisted `(submitted_at, id)` descending, max 100, with a validated
  opaque cursor. Register validated signal arrays under a new opaque artifact ID.
- Implement preview bounds (start >= 0, 1 <= limit <= 168), variable allowlist,
  metadata and monthly summaries with valid/expected counts. No wind-direction mean.
- Export deterministic OpenAPI JSON from an injected temporary-data-root app;
  do not open credentials or submit jobs. Add schema assertions for every REST route.
- Run the targeted tests and existing API/jobs/EPW tests; commit
  `fix(api): add typed UI job history and artifact previews`.

## Task 2 — Small reusable shell and typed client

**Interfaces:** `apiClient` exposes geocode/discover/plan/submit/getJob/listJobs/
cancelJob/uploadBaseline/uploadSignals/preview/download using generated REST types.

selection, layout and appearance. No provider logic belongs in stores.

- Inspect the reference revision for drift; inventory adapted files and their

  patterns. Remove EnergyAtlas workbench imports and all reference storage keys.
- Scaffold only the dependencies in the design. Generate `schema.d.ts` from
  exported OpenAPI using a pinned `openapi-typescript` development dependency.
  Record the generator version and license with the frontend toolchain.
- Add tests for `401`, domain error JSON, malformed/HTML responses, aborts,
  theme/layout restore and reset, unknown saved layout version and keyboard focus.
  Example assertion: `expect(screen.getByRole('link', {name: 'Source Code'}))
  .toHaveAttribute('href', 'https://github.com/Energy-Atlas/openepw')`.
- Implement the header, Request dock, Map/Results center tabs and Agent dock.
  Use reference tokens and Geist; System plus six appearances in one settings menu.
- Implement bounded fetch/error parsing; optional bearer token lives in memory,
  never localStorage or a VITE variable. Download through the same authenticated
  client and revoke temporary blob URLs after use.
- Run typecheck/lint and targeted component tests; verify the shell at desktop
  and compact widths. Commit `fix(ui): establish dockable OpenEPW shell`.

## Task 3 — Manual discovery-to-download vertical slice

**Files:** request/app/results modules; `ui/src/features/request/RequestPanel.test.tsx`,
`ui/e2e/retrieval.spec.ts`; extend `tests/unit/test_ui_api.py` where necessary.
**Interfaces:** `dispatch(action: UiAction): Promise<ActionResult>` is the shared
entry point. Define discriminated actions `discover(request)`, `planWeather(request)`,
`submitPlan(plan)`, `selectJob(id)`, `cancelJob(id)` and `selectArtifact(id)` in
`app/types.ts`. Results contain actual data or structured errors, never mock success.

- Write tests for coordinate entry, ambiguous geocoding, provider credential
  errors, plan invalidation after edits, out-of-order discovery and duplicate Run.
  Concrete invariant: after changing the year, Run is disabled until a new plan
  succeeds; resolving the old discovery promise cannot restore the old plan.
- Implement explicit location choice and existing-weather form, provider/product
  choices, fixed-offset entry, advanced variables/hybrids and validated request JSON.
  Unsupported options explain their restriction; unknown availability stays unknown.
- Render discovery alternatives and review actual plan task/output counts,
  source limitations and estimated work before an explicit Run action.
- Bind one stable idempotency key to each submit intent; disable duplicate Run,
  reconcile a lost response by retrying the same key. Intentional rerun uses a new key.
  Invalidate old plan state whenever the request changes.
- Poll the selected job with bounded backoff, pause on connection failure and
  stop on terminal state. Restore server history from GET /v1/jobs. Preserve partial
  outputs and display cancellation-requested separately from cancelled.
- Prove the real backend path with an injected deterministic provider, then one
  opt-in small Open-Meteo request. No fixture imports in production modules.
- Run component/API/browser tests; commit `fix(ui): connect weather requests to real jobs`.

## Task 4 — Map selection, source locations and 3D context

**Files:** map modules/tests and `ui/e2e/map.spec.ts`; optional additive sampler
route in `api/app.py` only if the preview cannot use the returned plan locations.
**Interfaces:** `selectionToLocations(selection)` serializes point/list/bbox/Polygon
geometry only. Existing Python sampling expands areas; JavaScript never duplicates it.
Map reads returned `SourceRef.location` and request/plan locations from app state.

- Test point/list edits, bbox ordering/dateline handling, polygon finish/cancel/
  undo-last, imported holes, invalid rings and cap errors. Do not advertise unsupported
  dateline-crossing polygons. Verify keyboard/text alternatives to pointer drawing.
- Adapt the map wrapper, theme-aware basemap/terrain hooks and actual attribution.
  Render requested versus resolved locations and known displacement distinctly.
  Unknown source cells get a message, not a fabricated polygon.
- Add projection/pitch/terrain controls in a compact map toolbar. Contextual
  buildings use actual supplied heights; exclude synthetic reference footprints.
- Preserve verified production worker-asset handling for the chosen MapLibre
  version. Keep map state across tab switches; resize after docking/compact transitions.
- Browser-test a tile failure and WebGL-unavailable path: coordinate entry and
  plan creation remain usable. Test dark/theme switching and attribution visibility.
- Run map unit/browser tests and production preview; commit
  `fix(ui): add geographic selection and contextual 3D map`.

**Interfaces:** extend UiAction with `uploadBaseline(file)`, `uploadSignals(file)`,
`planFuture(request)`, `previewArtifact(id)`; `submitPlan` dispatches by plan.kind.
All actions call the same typed client used by manual workflows.

- Write tests for uploaded and existing baselines, invalid files, required
  reference periods, incompatible SSP/RCP/method combinations and stale future plans.
  Assert method B 2050 displays 2045–2054 and method A displays 2036–2065.
- Implement future controls for typical/extreme/ensemble with method-specific
  parameters. Signal upload is an advanced explicit backend; sampled explains why
  unavailable. Surface source byte estimates before Run.
- Render bounded hourly charts and monthly summaries from preview responses.
  Show units, valid counts, offset/calendar and selected row range; gaps remain gaps.
  A noleap source-year label must not cause the browser to insert February 29.
- Render source lineage, licenses, QC severity, partial failures and all bundle
  downloads. Preserve the difference between requested and actual source locations.
- E2E-test a complete local-signal future job with synthetic baseline and a
  ten-artifact result fixture. Separately run one bounded opt-in real future job.
- Run targeted suites; commit `fix(ui): expose future weather and artifact inspection`.

## Task 6 — Scripted agent on shared actions

**Files:** agent modules/tests and `ui/e2e/agent.spec.ts`.
**Interfaces:** `runRecipe(recipeId, context, dispatch)` awaits UiAction results;
context contains current draft, reviewed plan and selected artifact IDs. Recipes
cannot write app state except through dispatch or their own transcript state.

- Test that each recipe emits the same actions/requests as the corresponding
  manual operation. Spy on dispatch and assert ordered calls and exact plan identity.
- Adapt transcript/tool-result presentation, but replace reference sessions,
  timers, fake stage runner, model choices and permission-mode menus entirely.
- Implement the five recipes in the design. Parameters use the existing request
  form; no arbitrary natural-language interpretation. Display Scripted explicitly.
- Record success only after actual success; a failed step stops dependent steps
  and offers a meaningful retry. No cosmetic time delays or fictional reasoning.
- Test cancellation during discovery and after submission separately: discovery
  abort stops client work; an existing job requires POST cancel and further status
  polling. Reloaded pending Run prompts expire instead of executing automatically.
- Run parity/agent/browser tests; commit `fix(ui): run scripted workflows through shared actions`.
