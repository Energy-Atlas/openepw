# Map-first chat UI local validation

**Branch:** `feature/chat-ui`, based on `feature/mcp` commit `516e0ed`.
**Status:** Local implementation review; no merge or publication. The
[approved plan](../plans/2026-09-26-guided-weather-chat-ui.md) remains the
scope reference. The ignored `.env` was read by the local Python service and
was not edited or copied into browser files.

## Verified journeys

- A fresh browser tab opened on a full-canvas MapLibre globe with one fixed
  chat rail and no mode selector. The public OpenFreeMap `positron` and `dark`
  styles rendered. The `3d` style URL returned 404, so the sixth appearance
  uses a working dark style with distinct OpenEPW tokens.
- `40.0000,-105.3000 historical 2018` retained the coordinates, product and
  year in one turn. The user clicked `Assess and review plan` and then `Run
  reviewed plan`. Catalog tool call/result and plan events appeared before the
  job; provider retrieval began only after Run. The live Open-Meteo ERA5 job
  completed one output and showed its verified manifest row and QC caveat.
- The browser downloaded one EPW to the user's Downloads folder with a
  semantic filename and downloaded `compact.zip` through the `Download all
  successful` action. The local REST compact export returned a verified ZIP
  artifact (185,543 bytes) with HTTP `application/zip` and attachment headers.
  These actions transferred existing server artifacts; they did not fetch
  provider weather again.
- A monthly GHI prepared view opened in a floating panel while the chat stayed
  visible. It showed `Wh/m2`, 12 monthly points, 8,760/8,760 valid hours,
  source, year and Gregorian calendar. `where is my file?` used the current
  job context. A separately uploaded EPW appeared as `User EPW` and produced
  its own prepared monthly view without an invented provider.
- A two-point WGS84 GeoJSON upload was accepted by the Python service and the
  chat showed two exact service-accepted points before any new Run action.
- The revised queued-turn REST path processed `40,-105 historical 2018` and
  resumed the same browser session with both integer coordinates and year.
  Synthetic tests hold one turn while a second waits, withdraw the second,
  and check that the queue SQLite file contains no raw key assignment.
- Choosing a map point persisted its exact coordinates and focused the map at
  zoom 11. `District view` then became available. The live 3D view sampled
  three public basemap buildings; terrain remained visible after a pan, with
  the map still reporting ready at zoom 15.4. The move handler updates solar
  lighting without resetting the terrain source on every pan.
- At `40,-105.3`, live Mapterhorn terrain rendered at district zoom. Public
  vector buildings and a bounded geometric shadow pass were active. Changing
  appearance with terrain enabled initially blanked the map; the code now
  restores terrain after the new base style becomes idle, and a live light to
  dark to light check kept the terrain scene visible. The map status and
  attribution remained visible. A deterministic synthetic geometry test checks
  ground direction, roof intersection, night and relief ray occlusion.

The live browser was the Codex in-app browser on Windows at approximately
1280×720. These checks validate the observed journeys, not all device/GPU or
provider combinations. The two browser downloads were local testing artifacts
and were not committed.

## Open acceptance limits

- The shadow strategy changed from the proposed custom-depth prototype to
  bounded vector projection and DEM ray sampling. Live district screenshots
  show terrain and building context, but do not prove exact shadow alignment,
  neighboring wall occlusion, tile-edge continuity, distant relief shadows or
  sustained performance on other GPUs. See [decision 0004](../decisions/0004-map-first-chat-scene.md).
- The server persists a bounded FIFO for chat turns, including idempotent
  retries and withdrawal before execution. Concurrent changes to maps, plans,
  and other non-turn actions still return a stale revision for user review.
- Offline parsing covers common place, coordinate, product and year phrases;
  the optional model parser handles broader language when configured. The UI
  has not been user-tested for all multi-intent and correction phrasings.
- A terrain tile failure and every appearance at both globe and district
  zoom have not yet been visually inspected. External map services have no
  local SLA. Source-scope outlines remain documentary, not point eligibility.
- Chart drag, resize and keyboard operations are implemented; automated browser
  accessibility coverage is limited to the controls and fallback table rather
  than a full assistive-technology audit.

## Map and chat refinement

- The scene now seeds day and time from UTC. A live globe drag kept the displayed
  UTC time at 03:36 while the local sun elevation changed from −32° to +51°.
  Three-dimensional lighting and shadows use the same UTC state and recompute
  for the new map center.
- The geography toolbar appeared only after `Map` was selected in the composer,
  and closed back to the ordinary scene panel. The two header upload actions
  became one composer attachment control for EPW or GeoJSON. Transcript messages,
  tool calls, choices, plans and jobs use a common conversation layout.
- A new read-only `/v1/catalog/scopes` route returns documented footprints from
  the active catalog for the initial map, plus the source datasets without
  mappable geometry. The local snapshot had two CDS rectangles and nine
  unmapped source datasets. The browser normalizes the documented 0–360
  longitude convention and draws each mapped source as a faint scope layer.
  See the follow-up check below for the live overlay result.
- Focused availability/API tests: 20 passed. Browser tests: 32 passed across
  nine files. Browser production build and focused Ruff checks passed. Vite
  reported its existing large MapLibre/ECharts chunk warning.

## Follow-up: live catalog overlay and conversation reset (2026-09-27)

- After restarting the local API, `/v1/catalog/scopes` returned 200 with the
  same two CDS footprints and nine unmapped datasets. The legend rendered, but
  the map initially had **no** `openepw-evidence` source or layers. MapLibre's
  `isStyleLoaded()` is false while any tile source is loading and just after a
  source is added. The overlay effects used it as their guard, so they skipped
  and were never re-run. The candidate, drawing, selection and appearance
  paths had the same race. They now require only a parsed style
  (`getStyle()`), which is the condition that `addSource` enforces. The shadow
  renderer uses the same guard and says "Loading district tiles for shadows."
  instead of "Building geometry unavailable" until tiles finish. After a
  reload, all seven OpenEPW overlay layers existed and eight scope-fill tile
  features rendered on the globe once the map went idle.
- The bottom-left scope legend covered the zoom-in control, and the map status
  overlapped the navigation control and attribution. The legend, status,
  shadow status and attribution now stack beside and above the navigation
  control. A live box measurement found no overlaps in flat or 3D view. On
  narrow viewports the attribution now sits above the chat sheet instead of
  under it.
- District shadows were not re-inspected visually: the browser pane was hidden,
  so the page stayed `document.hidden` and MapLibre did not load tiles at zoom
  15.5. The loading and unavailable states are covered by unit tests.
- Conversation reset: the browser stores only the session ID, in per-tab
  `sessionStorage`. Reloading kept the same session. A new tab starts a new
  session. Removing `openepw-chat-session` and reloading created a fresh
  empty session while the earlier session kept its two events on the server.
  The UI has no **New chat** control and no way to reopen an earlier session.
  Old jobs and artifacts stay in the data root.
- Browser tests: 35 passed across ten files, including a fake-MapLibre overlay
  test and two shadow-status tests. Typecheck and Vite build passed with the
  existing chunk-size warning.
